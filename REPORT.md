# Отчёт по практической работе: окружения и зависимости Python

- Poetry: 2.5.1.
- Poetry-проект использует диапазон Python `>=3.12,<3.13`.

Оба проекта использовали локальное виртуальное окружение `.venv` внутри соответствующего проекта.

- `poetry_project/.venv`: `C:\Катя\виш\mlOPS\practice_2\poetry_project\.venv\Scripts\python.exe`

В обоих окружениях использовался Python 3.12.

## 3. Прямые зависимости

Исходный скрипт использует следующие прямые зависимости:

- `requests` — выполнение HTTP-запроса к Open-Meteo;
- `pandas` — создание и обработка `DataFrame`, сохранение CSV;
- `matplotlib` — построение графика.

`numpy` не добавлялся как прямая зависимость, потому что исходный код непосредственно не импортирует этот пакет. Он устанавливается как транзитивная зависимость библиотек проекта.

В Poetry-проекте зафиксированы основные зависимости:

- `requests >=2.34.2,<3.0.0`;
- `pandas >=3.0.6,<4.0.0`;
- `matplotlib >=3.11.2,<4.0.0`.

## 4. Примеры транзитивных зависимостей

По `poetry.lock`:

- `requests` зависит, в частности, от `urllib3`;
- `pandas` зависит, в частности, от `numpy`;
- `matplotlib` зависит, в частности, от `contourpy`.

## 5. Pip: фиксация и восстановление

Для `pip_project` были установлены библиотеки, необходимые исходному скрипту. `requirements.txt` содержит точные версии пакетов текущего окружения.

После удаления локального `.venv` было создано новое окружение и зависимости восстановлены из `requirements.txt`. После восстановления основной скрипт запускался без ручного добавления отдельных библиотек.

Результат работы программы:

- создан `temperature_24h.csv`;
- CSV содержит столбцы `time` и `temperature_c`;
- CSV содержит 24 строки данных;
- построен график температуры.

## 6. Poetry: группы зависимостей

В `pyproject.toml` зависимости разделены на группы:

- основная группа: `requests`, `pandas`, `matplotlib`;
- `test`: `pytest`;
- `dev`: `ruff`.

Проверка групп выполнялась в трёх вариантах:

| Установленные группы | pytest | ruff | Основной скрипт |
|---|---|---|---|
| только main | нет | нет | да |
| только test | да | нет | нет |
| test + dev | да | да | да |

После эксперимента полное окружение было восстановлено.

## 7. Изменение зависимости в пункте 9

Для точечного обновления была выбрана прямая зависимость `requests`.

Ограничение было задано как `^2.34.2`, что соответствует диапазону `>=2.34.2,<3.0.0`. Таким образом, разрешены совместимые обновления внутри ветки 2.x, но версия 3.x не разрешена.

Команды обновления не привели к изменению lock-файла:

- установленная версия `requests` осталась `2.34.2`;
- `pyproject.toml` не получил нового ограничения сверх уже существовавшего диапазона;
- транзитивные зависимости не изменились.

`poetry show --outdated` не обнаружил доступного обновления, поэтому отсутствие изменения версии является допустимым результатом задания. Установленная версия `2.34.2` соответствует диапазону `>=2.34.2,<3.0.0`, а следующая мажорная версия 3.x этим диапазоном запрещена.

## 9. Сравнение `venv + pip` и Poetry

`venv + pip` обеспечивает изоляцию окружения, а `requirements.txt` фиксирует конкретные версии пакетов для последующего восстановления.

Poetry дополнительно хранит декларативные ограничения зависимостей в `pyproject.toml` и точное разрешение зависимостей в `poetry.lock`. Это позволяет отделять основные зависимости проекта от тестовых и разработческих инструментов и воспроизводить согласованный набор пакетов.

Таким образом, оба подхода позволяют восстановить изолированное окружение, но Poetry предоставляет более структурированное управление зависимостями и lock-файл с точным разрешением версий.
